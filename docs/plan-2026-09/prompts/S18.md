# S18 — Bandeja mínima para moderadores

Estado inicial: pendiente. Potencia: **T2 — Sol / medium**. Atención estimada: 4 h; no es duración de una única sesión. Ruta principal.
Dependencias: S05, S07. Revisión humana no se sustituye por modelos.

## Prompt para el agente

Trabaja únicamente en **S18**. Lee `prompts/BASE.md`, `ESTADO.md`, `HANDOFF.md` y esta tarea. Si recibes el prompt compuesto, esos contenidos ya están incluidos. Confirma dependencias en `tasks.json` y evidencia antes de editar. No ejecutes toda la hoja de ruta.

**Resultado buscado:** dar un flujo usable para entender, corregir y documentar una alerta

**Ámbito de escritura:** dashboard/playground existente y rutas mínimas de revisión. Actualiza además los archivos de continuidad. No tocar otras áreas salvo dependencia mínima demostrada y documentada.

**Lectura dirigida:** 07-PRODUCTO-Y-PILOTO.md; rutas admin/feedback/evidence; UI actual. Los paths de producto se resuelven desde SDK o API según prefijo, no desde esta carpeta. No cargar documentos completos que no sean necesarios.

### Trabajo

1. Si S17 aún no existe, usa fixtures y contrato S05, sin simular backend terminado. Reutiliza UI existente; lista priorizada, detalle con turnos/evidencia/incertidumbre/versiones.
2. Permite BENIGN/RISK/INSUFFICIENT_CONTEXT y segunda revisión sin sobrescribir juicio previo.
3. Añade estados vacío/error/expirado/sin permiso y controles de accesibilidad.
4. Distingue recomendación del sistema de acción realizada por plataforma.

### Aceptación

- Un caso se revisa de extremo a extremo en modo fixture con registro; integración con cola S17 se valida en S20.
- Sin claves admin incrustadas ni datos sensibles en URL/log.
- Lenguaje no acusatorio; estado desconocido visible.
- No duplicar dashboard completo ni construir design system.

### Verificación y evidencia

Prueba manual reproducible de flujo con fixtures; prueba de autorización backend y captura local si ayuda. Build solo de UI afectada, usando protocolo largo si aplica. Guarda el resultado propio bajo `evidence/S18/` (crear al ejecutar) sin mensajes reales, secretos ni artefactos grandes. Registra versiones y comandos, distingue prueba ejecutada de recomendación. No hace falta guardar logs sensibles en Git.

### Límites y parada

No enviar notificaciones reales a menores/tutores/autoridades ni convertir revisión en bloqueo automático. Si una prueba/build/job probablemente supera 60 segundos, usa terminal persistente visible, guarda log/estado, marca WAITING_TERMINAL y termina el turno. No esperes haciendo polling. Si necesitas a un humano, marca BLOCKED_HUMAN y deja material concreto de revisión; no inventes respuesta ni avances la dependencia.

Al cerrar entrega: cambio realizado, evidencia, limitaciones y siguiente acción; actualiza `tasks.json`, `ESTADO.md`, `HANDOFF.md`, `CHANGELOG.md`. DONE solo cuando se cumpla la aceptación. No iniciar el siguiente prompt automáticamente.

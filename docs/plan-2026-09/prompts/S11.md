# S11 — Harness común para decisiones semánticas

Estado inicial: pendiente. Potencia: **T2 — Sol / medium**. Atención estimada: 4 h; no es duración de una única sesión. Ruta principal.
Dependencias: S05. Revisión humana no se sustituye por modelos.

## Prompt para el agente

Trabaja únicamente en **S11**. Lee `prompts/BASE.md`, `ESTADO.md`, `HANDOFF.md` y esta tarea. Si recibes el prompt compuesto, esos contenidos ya están incluidos. Confirma dependencias en `tasks.json` y evidencia antes de editar. No ejecutes toda la hoja de ruta.

**Resultado buscado:** comparar candidatos usando las mismas entradas, métricas y presupuesto

**Ámbito de escritura:** model-training y adaptadores de evaluación; fixtures de contrato. Actualiza además los archivos de continuidad. No tocar otras áreas salvo dependencia mínima demostrada y documentada.

**Lectura dirigida:** bakeoff_models.py, simulate_cascade.py, contrato S05, manifiesto S10 si está disponible; usar fixtures fake hasta entonces. Los paths de producto se resuelven desde SDK o API según prefijo, no desde esta carpeta. No cargar documentos completos que no sean necesarios.

### Trabajo

1. Extiende harness existente para baseline determinista, lineal/hash y adaptador tipado. No crear framework general.
2. Incluye LOW, no solo escalados. Controla truncación, orden de opciones y prompt español versionado.
3. Registra modelo/revisión/hardware, cold/warm, RAM, latencias, probabilidades brutas y calibración separada.
4. Implementa primero proveedor fake para validar IO, errores y mediciones; apaga red por defecto.

### Aceptación

- Todos los adaptadores reciben mismo contexto y contrato; corridas con datos reales requieren S10.
- Fixtures de error/truncación/timeout no cuentan como benignos.
- Métricas de decisión y costo separadas; schema no implica exactitud.
- Resultado JSON/tabla reproducible sin LLM juez obligatorio.

### Verificación y evidencia

Smoke test determinista con fake; tests de agregación a mano sobre matriz pequeña y comparación de IDs. No ejecutar modelos reales hasta S12. Guarda el resultado propio bajo `evidence/S11/` (crear al ejecutar) sin mensajes reales, secretos ni artefactos grandes. Registra versiones y comandos, distingue prueba ejecutada de recomendación. No hace falta guardar logs sensibles en Git.

### Límites y parada

Sin nuevos proveedores pagados, búsqueda de hiperparámetros automática ni más de dos candidatos nuevos. Si una prueba/build/job probablemente supera 60 segundos, usa terminal persistente visible, guarda log/estado, marca WAITING_TERMINAL y termina el turno. No esperes haciendo polling. Si necesitas a un humano, marca BLOCKED_HUMAN y deja material concreto de revisión; no inventes respuesta ni avances la dependencia.

Al cerrar entrega: cambio realizado, evidencia, limitaciones y siguiente acción; actualiza `tasks.json`, `ESTADO.md`, `HANDOFF.md`, `CHANGELOG.md`. DONE solo cuando se cumpla la aceptación. No iniciar el siguiente prompt automáticamente.

# S15 — Detección temprana por prefijos

Estado inicial: pendiente. Potencia: **T3 — Astra / medium**. Atención estimada: 4 h; no es duración de una única sesión. Ruta principal.
Dependencias: S10. Revisión humana no se sustituye por modelos.

## Prompt para el agente

Trabaja únicamente en **S15**. Lee `prompts/BASE.md`, `ESTADO.md`, `HANDOFF.md` y esta tarea. Si recibes el prompt compuesto, esos contenidos ya están incluidos. Confirma dependencias en `tasks.json` y evidencia antes de editar. No ejecutes toda la hoja de ruta.

**Resultado buscado:** medir cuándo aparece una alerta y si ocurre antes o después de evidencia suficiente

**Ámbito de escritura:** SDK benchmark temporal y fixtures anotados. Actualiza además los archivos de continuidad. No tocar otras áreas salvo dependencia mínima demostrada y documentada.

**Lectura dirigida:** temporal-layer.ts, actor-layer.ts, benchmark runner; rúbrica temporal S04; paper SCoRL como referencia conceptual. Los paths de producto se resuelven desde SDK o API según prefijo, no desde esta carpeta. No cargar documentos completos que no sean necesarios.

### Trabajo

1. Ejecuta cada conversación como prefijos 1..t sin futuro.
2. Usa primer turno de evidencia y evento crítico anotados; unknown se excluye de métrica temporal pero se cuenta.
3. Mide alarma prematura, retraso, omisiones y carga acumulada por conversación.
4. Haz ablación de actor/temporal/dampeners para atribuir contribución; no entrenar RL todavía.

### Aceptación

- Prueba que un mensaje futuro no modifica resultado pasado.
- Curvas por turno y definición inequívoca de denominador.
- Comparador de conversación completa no se presenta como detección temprana.
- Sin optimizar alertar desde el saludo.

### Verificación y evidencia

Fixtures cortos con instante esperado y replay reproducible; tests de timestamps desordenados/faltantes y reinicio. Guarda el resultado propio bajo `evidence/S15/` (crear al ejecutar) sin mensajes reales, secretos ni artefactos grandes. Registra versiones y comandos, distingue prueba ejecutada de recomendación. No hace falta guardar logs sensibles en Git.

### Límites y parada

No implementar memoria ilimitada ni cambiar reglas para acomodar test sin desarrollo separado. Si una prueba/build/job probablemente supera 60 segundos, usa terminal persistente visible, guarda log/estado, marca WAITING_TERMINAL y termina el turno. No esperes haciendo polling. Si necesitas a un humano, marca BLOCKED_HUMAN y deja material concreto de revisión; no inventes respuesta ni avances la dependencia.

Al cerrar entrega: cambio realizado, evidencia, limitaciones y siguiente acción; actualiza `tasks.json`, `ESTADO.md`, `HANDOFF.md`, `CHANGELOG.md`. DONE solo cuando se cumpla la aceptación. No iniciar el siguiente prompt automáticamente.

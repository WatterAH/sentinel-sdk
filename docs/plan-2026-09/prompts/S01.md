# S01 — Línea base y recuperación del trabajo local

Estado inicial: pendiente. Potencia: **T2 — Sol / medium**. Atención estimada: 3 h; no es duración de una única sesión. Ruta principal.
Dependencias: ninguna. Revisión humana no se sustituye por modelos.

## Prompt para el agente

Trabaja únicamente en **S01**. Lee `prompts/BASE.md`, `ESTADO.md`, `HANDOFF.md` y esta tarea. Si recibes el prompt compuesto, esos contenidos ya están incluidos. Confirma dependencias en `tasks.json` y evidencia antes de editar. No ejecutes toda la hoja de ruta.

**Resultado buscado:** tener una base reproducible sin perder ni mezclar los cambios anteriores

**Ámbito de escritura:** evidence/S01 y documentos de inventario; código solo si se solicita después. Actualiza además los archivos de continuidad. No tocar otras áreas salvo dependencia mínima demostrada y documentada.

**Lectura dirigida:** 02-ESTADO-ACTUAL.md; auditoría 2026-08-27; SDK package.json, workflows; API scripts y tests pertinentes. Los paths de producto se resuelven desde SDK o API según prefijo, no desde esta carpeta. No cargar documentos completos que no sean necesarios.

### Trabajo

1. Usa project-git-status sobre la carpeta padre; registra HEAD y refs locales, estado dirty y herramientas disponibles. Si el script no da detalle necesario, usa una consulta Git acotada.
2. Clasifica diff previo en motor, datos, seguridad, experimentos, UI y docs. Identifica archivos ignorados necesarios sin leer secretos. No git add global, reset, clean o stash.
3. Inspecciona comandos existentes, duración probable y efectos laterales. Registra hash de reportes/corpus y fecha; un SHA de HEAD solo no describe árbol dirty.
4. Verifica de forma de solo lectura el estado de distribución npm si se va a documentar; distingue publicado/local/privado. Propón agrupación de commits y respaldo seguro, sin publicarlos.
5. Ejecuta checks locales cortos y aislados si el entorno está preparado; los largos se lanzan con protocolo de terminal.

### Aceptación

- Inventario fechado y reproducible por repo, sin atribuir trabajo previo a esta sesión.
- Lista de comandos reales y grupos de cambios; contradicciones del estado resueltas o marcadas.
- Métricas existentes identificadas como históricas; resultados nuevos acompañados de comando/fecha.
- Baseline sin secretos y restauración propuesta antes de modificaciones profundas.

### Verificación y evidencia

Reutiliza SDK `npm run typecheck`, `npx --no-install vitest run src/`, `npm run bench` cuando corresponda; API con DB temporal en memoria y proveedores simulados, tras inspeccionar tests. Registrar cualquier archivo de reporte que el benchmark modifique. Guarda el resultado propio bajo `evidence/S01/` (crear al ejecutar) sin mensajes reales, secretos ni artefactos grandes. Registra versiones y comandos, distingue prueba ejecutada de recomendación. No hace falta guardar logs sensibles en Git.

### Límites y parada

No instalar dependencias a ciegas ni tocar producción. Si hay cambios imposibles de atribuir, preservarlos y documentar la duda; no impedir el inventario seguro. Si una prueba/build/job probablemente supera 60 segundos, usa terminal persistente visible, guarda log/estado, marca WAITING_TERMINAL y termina el turno. No esperes haciendo polling. Si necesitas a un humano, marca BLOCKED_HUMAN y deja material concreto de revisión; no inventes respuesta ni avances la dependencia.

Al cerrar entrega: cambio realizado, evidencia, limitaciones y siguiente acción; actualiza `tasks.json`, `ESTADO.md`, `HANDOFF.md`, `CHANGELOG.md`. DONE solo cuando se cumpla la aceptación. No iniciar el siguiente prompt automáticamente.

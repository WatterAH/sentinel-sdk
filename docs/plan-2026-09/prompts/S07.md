# S07 — Aislamiento y ownership del piloto

Estado inicial: pendiente. Potencia: **T4 — Astra / high**. Atención estimada: 5 h; no es duración de una única sesión. Ruta principal.
Dependencias: S05. Revisión humana no se sustituye por modelos.

## Prompt para el agente

Trabaja únicamente en **S07**. Lee `prompts/BASE.md`, `ESTADO.md`, `HANDOFF.md` y esta tarea. Si recibes el prompt compuesto, esos contenidos ya están incluidos. Confirma dependencias en `tasks.json` y evidencia antes de editar. No ejecutes toda la hoja de ruta.

**Resultado buscado:** elegir y probar aislamiento por cliente antes de operar datos compartidos

**Ámbito de escritura:** API auth, modelos/rutas/servicios afectados, migración local y pruebas. Actualiza además los archivos de continuidad. No tocar otras áreas salvo dependencia mínima demostrada y documentada.

**Lectura dirigida:** API security.py, db_models.py, evidence_service.py, network_service.py, routes/messages_crud.py; 04-ARQUITECTURA.md. Los paths de producto se resuelven desde SDK o API según prefijo, no desde esta carpeta. No cargar documentos completos que no sean necesarios.

### Trabajo

1. Traza credencial→cliente→sesión→evidencia/feedback/red en rutas concretas. No asumir que scope=client limita pertenencia.
2. Decide instancia aislada por piloto o tenancy explícita. Registra ADR con costo/migración.
3. Para tenancy, el tenant viene de credencial verificada y todas las lecturas/escrituras lo filtran; HMAC/namespace por cliente. Para aislamiento por despliegue, documenta fronteras/secretos/DB separadas y prohíbe mezclar clientes.
4. Revisa que navegador no reciba claves admin. Prepara migración reversible local si hace falta.

### Aceptación

- Prueba de dos clientes con mismos IDs no permite cruce, o configuración verificable de instancias separadas con prueba equivalente.
- Evidencia, informes y red incluidos, no solo /analyze.
- Migración no toca producción; datos antiguos no se asignan arbitrariamente.
- Revisión fuerte documentada de rutas y fallos.

### Verificación y evidencia

Tests de acceso horizontal, credenciales revocadas, IDs ajenos, consultas de red y rollback en DB temporal. Revisar diff final contra mapa de ownership. Guarda el resultado propio bajo `evidence/S07/` (crear al ejecutar) sin mensajes reales, secretos ni artefactos grandes. Registra versiones y comandos, distingue prueba ejecutada de recomendación. No hace falta guardar logs sensibles en Git.

### Límites y parada

Si la solución excede cinco horas, elegir instancia aislada para el piloto y diferir multitenancy con decisión concreta; no entregar aislamiento parcial como completo. Si una prueba/build/job probablemente supera 60 segundos, usa terminal persistente visible, guarda log/estado, marca WAITING_TERMINAL y termina el turno. No esperes haciendo polling. Si necesitas a un humano, marca BLOCKED_HUMAN y deja material concreto de revisión; no inventes respuesta ni avances la dependencia.

Al cerrar entrega: cambio realizado, evidencia, limitaciones y siguiente acción; actualiza `tasks.json`, `ESTADO.md`, `HANDOFF.md`, `CHANGELOG.md`. DONE solo cuando se cumpla la aceptación. No iniciar el siguiente prompt automáticamente.

# S02 — Comandos repetibles y entrega de terminal

Estado inicial: pendiente. Potencia: **T1 — Luna / low**. Atención estimada: 2 h; no es duración de una única sesión. Ruta principal.
Dependencias: S01. Revisión humana no se sustituye por modelos.

## Prompt para el agente

Trabaja únicamente en **S02**. Lee `prompts/BASE.md`, `ESTADO.md`, `HANDOFF.md` y esta tarea. Si recibes el prompt compuesto, esos contenidos ya están incluidos. Confirma dependencias en `tasks.json` y evidencia antes de editar. No ejecutes toda la hoja de ruta.

**Resultado buscado:** reusar las utilidades ya preparadas y hacer mecánica la ejecución de comprobaciones

**Ámbito de escritura:** scripts del SDK/API necesarios y 08-AGENTES-Y-CUOTA.md. Actualiza además los archivos de continuidad. No tocar otras áreas salvo dependencia mínima demostrada y documentada.

**Lectura dirigida:** scripts/sentinel_plan.py, scripts/run_local_job.py; package.json; API scripts/run_calibration.sh. Los paths de producto se resuelven desde SDK o API según prefijo, no desde esta carpeta. No cargar documentos completos que no sean necesarios.

### Trabajo

1. Ejecuta primero `python3 scripts/verify_plan_tools.py`; ya cubre éxito, fallo, comando inexistente, cancelación y validación de dependencias. No dupliques estas pruebas sin una razón.
2. Documenta comandos de test, bench y entrenamiento desde el inventario S01; comprueba cwd y variables mínimas.
3. Si se repite una secuencia, añade un script pequeño de comandos conocidos con salida/exit code. No crear otro runner general ni un orquestador.
4. Ensaya entrega visible de terminal y reanudación leyendo una sola vez resultado; documenta diferencias del agente utilizado.

### Aceptación

- Código de salida real preservado, log y estado final legibles.
- Comandos largos no requieren un modelo esperando.
- Error y cancelación no se reportan como éxito; no se lanzan dos jobs por reintentar una sesión.
- Sin acceso a base productiva ni credenciales en ejemplos.

### Verificación y evidencia

Smoke tests acotados de utilidades; no ejecutar toda la suite de producto para validar documentación. Guarda el resultado propio bajo `evidence/S02/` (crear al ejecutar) sin mensajes reales, secretos ni artefactos grandes. Registra versiones y comandos, distingue prueba ejecutada de recomendación. No hace falta guardar logs sensibles en Git.

### Límites y parada

Si la herramienta no puede conservar una terminal visible, deja comando listo para que Luis lo ejecute; no simules que existe un proceso persistente. Si una prueba/build/job probablemente supera 60 segundos, usa terminal persistente visible, guarda log/estado, marca WAITING_TERMINAL y termina el turno. No esperes haciendo polling. Si necesitas a un humano, marca BLOCKED_HUMAN y deja material concreto de revisión; no inventes respuesta ni avances la dependencia.

Al cerrar entrega: cambio realizado, evidencia, limitaciones y siguiente acción; actualiza `tasks.json`, `ESTADO.md`, `HANDOFF.md`, `CHANGELOG.md`. DONE solo cuando se cumpla la aceptación. No iniciar el siguiente prompt automáticamente.

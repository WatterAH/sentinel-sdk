# S22 — Demo y dossier para foro

Estado inicial: pendiente. Potencia: **T1 — Luna / low**. Atención estimada: 3 h; no es duración de una única sesión. Ruta principal.
Dependencias: S21. Revisión humana no se sustituye por modelos.

## Prompt para el agente

Trabaja únicamente en **S22**. Lee `prompts/BASE.md`, `ESTADO.md`, `HANDOFF.md` y esta tarea. Si recibes el prompt compuesto, esos contenidos ya están incluidos. Confirma dependencias en `tasks.json` y evidencia antes de editar. No ejecutes toda la hoja de ruta.

**Resultado buscado:** tener una demostración honesta y reproducible que enseñe la contribución de Sentinel

**Ámbito de escritura:** documentación/demo fixtures y guion; no narrativa de marketing sin evidencia. Actualiza además los archivos de continuidad. No tocar otras áreas salvo dependencia mínima demostrada y documentada.

**Lectura dirigida:** 07-PRODUCTO-Y-PILOTO.md; informes de evaluación; dataset/model cards. Los paths de producto se resuelven desde SDK o API según prefijo, no desde esta carpeta. No cargar documentos completos que no sean necesarios.

### Trabajo

1. Prepara cinco escenarios ficticios y guion de siete minutos.
2. Muestra pares culturales, secuencia temporal, abstención, revisión y fallo/rollback.
3. Produce resumen español e inglés, diagrama y tabla de resultados con intervalos y limitaciones.
4. Añade comando de demo offline y versión/hash; no incorporar chats reales.

### Aceptación

- Demo funciona sin credenciales ni API externas obligatorias.
- Cifras provienen de informes identificados.
- Se diferencia actual/experimental/futuro y se muestran errores.
- No claims de primer sistema, precisión universal o cumplimiento legal automático.

### Verificación y evidencia

Ensayo completo manual con temporizador y verificación de enlaces/cifras mediante scripts. Si no existen métricas nuevas, usar históricas fechadas o no poner cifra. Guarda el resultado propio bajo `evidence/S22/` (crear al ejecutar) sin mensajes reales, secretos ni artefactos grandes. Registra versiones y comandos, distingue prueba ejecutada de recomendación. No hace falta guardar logs sensibles en Git.

### Límites y parada

No publicar sitio, vídeo o deck automáticamente; entregar paquete local revisable. Si una prueba/build/job probablemente supera 60 segundos, usa terminal persistente visible, guarda log/estado, marca WAITING_TERMINAL y termina el turno. No esperes haciendo polling. Si necesitas a un humano, marca BLOCKED_HUMAN y deja material concreto de revisión; no inventes respuesta ni avances la dependencia.

Al cerrar entrega: cambio realizado, evidencia, limitaciones y siguiente acción; actualiza `tasks.json`, `ESTADO.md`, `HANDOFF.md`, `CHANGELOG.md`. DONE solo cuando se cumpla la aceptación. No iniciar el siguiente prompt automáticamente.

## Prompt para el agente

Trabaja únicamente en **S05**. Lee `prompts/BASE.md`, `ESTADO.md`, `HANDOFF.md` y esta tarea. Si recibes el prompt compuesto, esos contenidos ya están incluidos. Confirma dependencias en `tasks.json` y evidencia antes de editar. No ejecutes toda la hoja de ruta.

**Ámbito de escritura:** tipos/contratos SDK y modelos API estrictamente necesarios; ADR. Actualiza además los archivos de continuidad. No tocar otras áreas salvo dependencia mínima demostrada y documentada.

### Trabajo

1. Mapea contrato actual SDK/API; conserva enums públicos o diseña adaptador versionado.
2. Define schema de candidato con abstención, timeout, versión y evidence_refs existentes. No exponer logit como probabilidad calibrada.
3. Especifica shadow/review/enforce y defaults; el candidato comienza shadow.
4. Documenta cómo se resuelve desacuerdo con reglas existentes y cómo auditarlo sin borrar señales. Implementa tipos/validadores mínimos, no un proveedor real.

### Aceptación

- Fixtures compartidos aceptados/rechazados por ambos lados.
- Compatibilidad existente demostrada o migración explícita.
- Modo sombra no modifica riesgo, intervención ni tráfico de red por defecto.
- Errores y contexto insuficiente quedan distinguibles.

### Verificación y evidencia

Pruebas dirigidas de serialización/paridad, campo ausente, enum desconocido, score fuera de rango y referencias inexistentes; typecheck SDK si cambian tipos. Guarda el resultado propio bajo `evidence/S05/` (crear al ejecutar) sin mensajes reales, secretos ni artefactos grandes. Registra versiones y comandos, distingue prueba ejecutada de recomendación. No hace falta guardar logs sensibles en Git.

### Límites y parada

No promover candidato, cambiar umbrales o incorporar LLM al dispositivo en esta tarea. Si una prueba/build/job probablemente supera 60 segundos, usa terminal persistente visible, guarda log/estado, marca WAITING_TERMINAL y termina el turno. No esperes haciendo polling. Si necesitas a un humano, marca BLOCKED_HUMAN y deja material concreto de revisión; no inventes respuesta ni avances la dependencia.

Al cerrar entrega: cambio realizado, evidencia, limitaciones y siguiente acción; actualiza `tasks.json`, `ESTADO.md`, `HANDOFF.md`, `CHANGELOG.md`. DONE solo cuando se cumpla la aceptación. No iniciar el siguiente prompt automáticamente.
